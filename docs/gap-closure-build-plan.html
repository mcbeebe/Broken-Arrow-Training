§0

The plan in one paragraph

Wave 1 ships four user-visible trust wins in weeks, not months — week-batch Garmin push with auto re-push on every plan edit (nobody in the market re-pushes on adaptation), a realignment card that fires at 1–2 misses (Runna waits for >3), readiness reds that always carry a one-tap action, and three free public calculators as the acquisition funnel — while the Season Engine's data model lands invisibly underneath. Wave 2 builds the centerpiece: a derived-state season engine that chains RACE → RECOVER → BRIDGE → BUILD → TAPER with residual-aware bridges (Issurin · Bickel · Hickson · Friel, all pinned in tests), able to periodize a running race and a Hyrox in one season — which no app on the market can represent. Wave 3 stacks the differentiators on top: GAP-corrected adaptive pace targets, a trail race-pacing card with fueling checkpoints that Garmin doesn't produce and Runna explicitly declines, a gray-zone guard, and Apple WorkoutKit from the same structured-workout source as Garmin.

The non-negotiable

A feature is "done" only when a test asserts the athlete-facing output changes correctly and conditionally — a three-race season chains through explicit blocks and a single-race athlete's plan is byte-identical to today's; a missed key session produces a realignment card within 24 h and a completed one produces nothing; a plan edit re-pushes changed workouts and untouched days are not re-sent. For delivery gaps: the workout reaches the wrist/screen and never goes stale.

Centerpiece 1 — the multi-race Season Engine (G1)

The market's premium feature (TrainingPeaks ATP; Humango's $28.99/mo tier), absent in Runna and Garmin — and nobody periodizes running + Hyrox in one season. Attune already owns both engines, the post-race recovery formulas, phase-aware strength, and a real TSB engine. The Season Engine chains them:

RACEA/B/C priority→ RECOVERshipped R5 · reverse taper→ BRIDGEresidual-aware · category-first→ BUILDcompressed · ≥8 wk to peak→ TAPERTSB tiers A +15..25 · B −10..0→ RACEnext event

The science, pinned in tests

  • Issurin residuals (Sports Med 2010): aerobic 30±5 d · max strength 30±5 d · glycolytic 18±4 d · strength-endurance 15±5 d · speed 5±3 d — bridge content chosen by next-race demands vs. decaying residuals.
  • Bickel 2011: strength holds at 1×/wk once built → the Hyrox→marathon bridge keeps exactly one strength day while run volume rebuilds.
  • Hickson 1981: aerobic holds on 2–4 d/wk if intensity is preserved → the half→Hyrox bridge keeps 1–2 intensity touches while strength-endurance/glycolytic (15–18 d residuals) train last.
  • Friel taper tiers via TSB: A +15..+25 · B −10..0 · C trained through — computable today from the shipped performance engine.

The design decision that beats Garmin

Season state is derived, never stored — recomputed from (races, today, loggedActuals) on every read. No mutable "current state" means the engine cannot wedge: the explicit answer to Garmin's documented post-race "stuck in recovery" failures.

Plus season-level feasibility honesty: "two A races 5 weeks apart — the second gets a compressed build; consider B-tagging one" (the exact failure TrainerRoad/Athletica users hit), and a SEASON coach section — no competitor's AI can explain a season.

§4

The 14 specs (summaries — full specs in the markdown twin)

G1a — Season Engine: state machine + residual-aware bridges L PR-6

Pure-TS src/engines/season/: planSeason(races, config, today) chains RECOVER (wraps shipped R5 formulas into generated weeks) → BRIDGE (Issurin residual table + Bickel/Hickson maintenance doses select content by next-race demands) → BUILD (existing generators, compressed runway, ≥8 wk to peak) → TAPER (Friel TSB tiers). B races: mini-taper + tune-ups 4–6 wk out; C races trained through; <10-day proximity rule. Season feasibility advisories. Guard: a single-race plan is byte-identical to today's.

✅ massive — every racer books multiple events; hybrid is fastest-growing✅ visceral — the post-race "now what?" void✅ "plan my season" · "my A race"

G1b — Season surface: race calendar + multi-race onboarding + SEASON coach narration M/L PR-7

A/B/C race calendar with block-timeline strip; B-race taper + tune-up stamps in the plan; onboarding gains "add another race?"; build_context_block gains a SEASON section — the coach explains why today serves the next race. Single-race athletes see no season UI (guard).

G2a — Garmin push UX: week batch + auto re-push on edit S/M PR-2 · ship first

"Send week to watch" batching the shipped payload builder; pushed-day ledger diffs on every applied plan edit (one seam catches coach proposals, realignment, repace, season re-chain) and re-pushes exactly the changed days. Offered at onboarding-complete and after every applied proposal.

✅ execution happens on-wrist✅ "my watch still has the old workout"✅ "send it to my watch"

G4 — Realignment card at 1 key / 2 any misses M PR-3

Wires the shipped detectors (skipped_workout, compliance_drift) to author plan-edit proposals rendered as the shipped ProposalCard (Apply / Modify / Keep + undo + why). Never silent (plan-hash guard); "keep" suppresses for the week; applying re-pushes to the watch.

G3 — Onboarding as belief-building: goal-first + live personalized preview M/L PR-G3

Race/goal first; after ~5 questions a real generated week-1 preview + top-3 method match renders and visibly refines as questions continue; coach letter moves earlier; every non-plan-changing question deferred to contextual asks (NN/g). Golden harness proves identical answers ⇒ identical plan.

G5 — Performance-adaptive pace targets (trail-true) M PR-8

Rolling effective-VDOT from logged actuals — compliance-grade filtered, HR-compliant, GAP-corrected for trail (the input Runna doesn't have). Delivered only as an evidence-cited proposal ("your last 3 tempos ran 8 s/mi fast at compliant HR"); apply ⇒ repace.ts rewrites future targets only. Opt-in, targets-only, never restructures.

G6 — Course-aware trail pace bands + fueling checkpoints M/L PR-9

Per-segment grade-adjusted bands for the 3 Broken Arrow courses through Minetti cost, calibrated to the athlete's adaptive VDOT, with power-hike flags, fueling checkpoints summing to the race g/hr target, and heat/altitude cautions — a race card in race week + RACE_PACING coach section. Unmatched course ⇒ absent (guard).

G7 — Gray-zone guard + durability metric M PR-10

Weekly easy/hard split vs. a new per-method intensityTarget in all 9 method files ("Koop's plan wants your easy days easy: 82% target, you ran 61%"); aerobic decoupling (GAP-corrected pace:HR halves) on long runs → durability trend; INTENSITY coach section.

G8 — Readiness UX hardening S PR-4

Every red pairs with a one-tap concrete action (the deload program and daily adjustment already exist — make them the CTA); trend arrows everywhere; uncertainty framing; the two known color-only offenders fixed; plain-language defaults confirmed at every render.

G9 — Flexible consistency, no streaks S PR-4

"N of M sessions — rest days count" as the headline metric (planned rest already renders ✓); grace framing (1 flexed session doesn't fail the week); 4-week trend. Design rule encoded as a test: no streak counter, ever.

G10 — Free public calculators as the funnel M PR-5

Trail fueling planner, vert-adjusted finish predictor, race-day heat planner — pure-client Vite entries sharing the in-app engines (no copies), zero API calls (tested), shareable results, "get the full plan" CTA with referral param through signup.

G2b — Today surface + Morning Report S/M PR-11

Summary hardened into a today-first glanceable screen (readiness verdict → today's workout → "why this workout" one-liner); the shipped 6 AM push becomes the Morning Report deep-linking to it; the 8 PM push becomes tomorrow's evening preview; PWA shortcuts. Native widgets explicitly deferred.

G2c — Apple WorkoutKit push L PR-11

First factor a platform-neutral structuredWorkout.ts intermediate out of the Garmin builder (Garmin provably unchanged via payload snapshots), then WorkoutKit (iOS 17+) composes the same steps for the watch; auto re-push reuses the G2a diff. TestFlight-internal first; App Store review is an explicit external dependency.

§6

The eight locked architecture decisions

D1 · Season model, plan untouched

Season{races, blocks} is new top-level state; TrainingPlan stays the unit of generation/rendering tagged seasonBlockId. A single-race athlete is the degenerate one-race season — ~90 existing test files, compliance, push, and coach snapshot untouched.

D2 · Derived, never stored, state

The block machine recomputes from (races, today, actuals) on every read — no stored state to wedge. The anti-Garmin decision.

D3 · Regeneration never destroys history

Past weeks immutable; every regeneration splices future weeks only and flows through the one atomic proposal+undo write seam.

D4 · Pace write-back via the rezone seam

rezone.ts (HR strings) gets a repace.ts sibling for pace strings; calibratedVdot carries provenance; opt-in only.

D5 · One workout source, every watch

A platform-neutral structured-workout intermediate factored from the Garmin builder; Garmin and Apple render from it — a third platform is a renderer, not a rewrite.

D6 · Public calculators are pure-client

Extra Vite HTML entries, zero API calls — the MULTI_USER_TODO auth/rate-limit blockers stay out of the critical path. A calculator needing an API is out of scope by rule.

D7 · Vercel 12-function standing rule

No PR adds a serverless function; new behavior multiplexes into existing action switches.

D8 · Coach sections follow the shipped pattern

SEASON, RACE_PACING, INTENSITY join the ~20 named sections via buildCoachSnapshot → build_context_block, each locked by an L4 fixture-honesty test.

§7

Testing & traceability (the bar every PR clears)

L1 science math pinned to fact-checked values · L2 output-behavioral with a mandatory negative guard (single race ⇒ no season; completed workout ⇒ no ping; road course ⇒ no bands) · L3 golden-plan regression with three new season personas + a single-race-unchanged guard · L4 coach fixture-honesty for every new prompt section. A PR cannot merge if any cited theory lacks a passing test — the full Theory → Manifestation → Test matrix (17 rows: Issurin, Bickel, Hickson, Wilson, Friel tiers, 8-wk spacing, Runna's >3 threshold, no-streaks evidence, NN/g, Minetti, fueling tiers, non-color redundancy, orthosomnia-safe reds…) is in the markdown twin.

Golden-churn rule

PR-G3, PR-6, and PR-8 each regenerate docs/onboarding-ground-truth.json — never two of them in flight at once; every regeneration reviewed as a diff.

§8

Risks & the monetization note

Top risks

  • G1 is the biggest lift and the headline — mitigated by Wave 1's four visible wins while PR-1 lands quietly.
  • Monolith pressure — App.tsx (1,577 lines) and Onboarding.tsx both get touched; rule: no router introduction inside a feature PR.
  • Apple is externally gated (iOS 17+, App Store review) — scheduled last, internal-first.
  • Recalibration trust — G5 is opt-in + proposal-only, encoded as a plan-hash guard test (a target can never change without an applied card).
  • Storage migration — the season key is additive with a lazy shim; two-devices-one-migrated sync-merge tested.

Monetization (flag, not scope)

The market prices exactly this plan's centerpiece as premium: multi-event is TrainingPeaks-Premium-gated and Humango's $28.99/mo tier gate; self-serve anchors at ~$19.90/mo. The Season Engine (G1) + execution loop (G2) are the natural premium tier when pricing lands. No billing code in these 12 PRs — the one decision this plan forces: don't give G1 away by default once signup opens beyond the allowlist.
